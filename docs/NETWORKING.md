# Networking

## Transport Foundation
- **Primary Protocol:** `ENetMultiplayerPeer` (UDP) utilized for all high-frequency physics, platforming prediction, and state synchronization.

## Host Authority Model
- **Strict Host-Authoritative:** The designated Host calculates the absolute truth of the physics sandbox. 
- **Client Responsibilities:** Dumb terminals that transmit input states (axes, key presses, item interaction intents) and compute lateral interpolation locally for visual smoothness.
- **Host Responsibilities:** Validates all velocities, bounds, collisions, hazard interactions, role states, and the master `run_seed`.

## Replicating State
- **Bandwidth Control:** The Host broadcasts comprehensive positional state snapshots at a fixed tick frequency (e.g., 20 Hz). 
- **Discrete Events:** High-impact traversal and social events (bomb explosions, evidence manipulation, hazard pulses) are transmitted via reliable serialized RPCs to guarantee delivery.

## Interaction Validations & Guardrails
- **The One-Carry Rule:** The Host algorithmically rejects pickup, steal, or forge requests if the evaluating player physically holds an evidence artifact.
- **Proximity & Partitioning Verification:** Clients are prohibited from interacting with evidence objects spanning across cavern boundaries. The Host validates `room_slot` parity and distance geometry before applying state updates.

## Information Privacy & Public Event Filters
- **Timeline Filtering (Ambiguity Preservation):** When the Host logs environmental sabotage (e.g., a trap firing anomalously via Veil tampering), the timeline event is rigorously scrubbed (`actor_peer_id = -1`). The event shows *what* broke, never *who* broke it, ensuring the network protects the Veil's plausible deniability.
- **Public Meta Allowlists:** The Host enforces a stringent whitelist filtering payload metadata before broadcasting:
  - `artifact_spawned`/`artifact_picked`/`artifact_dropped`: Retains only `artifact_id`.
  - `artifact_stolen`: Retains `artifact_id` and `from_peer`.
  - `hazard_state_changed`: Enforced empty payload.
  - `evidence_checked`: Enforced empty payload (concealing the Warden's precise mathematical score).

## Role Secrecy Boundaries
- Role assignments are generated by the Host natively upon run initialization.
- Peer assignments are disseminated directly to respective clients via targeted *private* payload arrays (`rpc_id`). The local RAM of a client physically does not house the role values of other squad members.

## Determinism Foundations
- Authoritative execution uses `tick` and `event_id`. Real-world wall clock timings are discarded.
- Post-run lifecycles trigger strictly on spatial extraction zone conditions or mathematically rigid tick limits.
