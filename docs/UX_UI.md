## Shell Path
The current shell path remains:
- Home
- Profile
- Collection
- Archive
- Cosmetics
- Settings
- Lobby session state

No parallel shell surface should be added for Archive, relay culture, or world memory.

## Live Doctrine Carryover
The current shell already surfaces compact continuity around:
- challenge carryover
- crawl heat
- remembered pairs and crews
- public-safe doctrine and governance lines
- archive case memory and world focus

These remain part of the same shell path, not a second narrative browser.

## Shell Goals
- make continuity legible
- keep next action clear
- keep remembered runs, crawls, pairs, and world focus visible
- preserve compactness
- avoid turning the shell into a lore wall

## Home
Home should answer:
- what matters now
- what challenge or continuity pressure is live
- what to do next

## Profile and History
Profile should answer:
- who this player has become
- what crawl is active
- what pairs, crews, or obligations matter
- which runs are worth revisiting

## Collection
Collection remains the object browser.
- what this item or object is
- where it appears
- how it tends to matter

## Archive
Archive remains the interpretation browser.
- what happened
- what pattern matters
- what to watch next

## Lobby Continuity
The Lobby should feel like a continuing expedition culture using the existing surface:
- remembered public identity
- challenge carryover
- crawl heat
- crew or pair carryover
- safe, concise continuity lines

## Live Visual Governance
- [visual_governance.gd](d:/DeductionDelve/godot/src/visual/visual_governance.gd) currently owns shell title, symbol grammar, and shell palette helpers.
- The same doctrine also governs room packets, motion hierarchy, notebook-safe palette clamping, and entity presentation contracts.
- This is presentation governance only. It must not become a second gameplay layer.

## Guardrails
- no new UI surfaces
- no giant codex wall
- no mission board
- Layer-1-safe language only on public surfaces
