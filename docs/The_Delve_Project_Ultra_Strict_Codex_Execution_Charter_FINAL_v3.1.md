
# The Delve Project — Ultra-Strict Codex Execution Charter
## Constitutional Event Civilization Implementation Charter (FINAL v3.1)

**Status:** Authoritative implementation charter  
**Scope:** Next-wave architecture only  
**Audience:** Codex / implementation agents / repo stewards  
**Purpose:** Translate the finalized constitutional architecture into an enforceable execution contract that preserves power **without** permitting parallel architecture, abstraction drift, or overformalization.

---

## 0. Charter Priority

This charter is implementation-authoritative for the covered wave.

When this charter conflicts with:
- brainstorming language,
- design rhetoric,
- prior prompt prose,
- broad “add more systems” instincts,

**this charter wins.**

When this charter conflicts with existing repo reality:
- preserve repo truth,
- extend existing owners,
- document the conflict in `progress.md`,
- choose the interpretation that avoids parallel systems and preserves embodied-play primacy.

This charter does **not** authorize:
- second truth models,
- second shell pathways,
- second archive systems,
- detached governance simulators,
- philosophy engines implemented as independent runtime bureaucracy.

---

# 1. Mission

Implement the next-wave architecture so that The Delve Project functions as:

> a small number of sovereign civilizational stacks governing change, continuity, truth, habitation, renewal, embodiment, and stewardship; expressed through compact derived projections; constrained by hard constitutional laws; reviewed through stewardship lenses; and protected from overformalization wherever the attempt to formalize mercy, wonder, dignity, humility, or quiet legitimacy would itself damage the world.

Implementation must preserve:
- embodied expedition primacy,
- player action as a primary driver of continuity change,
- preserved totality without active clutter,
- layered truth without flattening,
- replayability through re-legibility and renewal rather than replacement,
- plural valid relations to play,
- long-horizon continuity,
- constitutional steerability.

---

# 2. Non-Negotiable Outcome

At the end of this wave, the repo must be able to support all of the following **through existing owner paths**:

1. A civilization-scale architecture that can evolve without deleting meaningful past structure.
2. Continuity that persists as layered influence rather than flat history logs.
3. Truth that is stratified, surface-budgeted, and challengeable.
4. Shell/home/archive/profile outputs that are compact projections of deeper stacks, not second authorities.
5. Embodied expedition play remaining the final cash-out of all higher-order meaning.
6. Explicit invariant enforcement in code and tests.
7. A phased implementation that is auditable, reversible, and hostile to parallel architecture.

---

# 3. Final Implementation Ontology

Every concept in this wave must belong to exactly one of these categories.

## 3.1 Active Architecture
Real owner-path logic with durable responsibilities.

## 3.2 Derived Projection
Computed packet/state/summary derived from active stacks. Important, but not sovereign.

## 3.3 Constitutional Law
Hard invariant. Must govern implementation, but must not become a peer runtime engine.

## 3.4 Stewardship Lens
Review/audit/evaluation criterion used in promotion, restoration, and governance decisions.

## 3.5 Forbidden Overformalization
Important concept that must shape architecture, but must **not** become independent live complexity.

If a concept appears in more than one category, that is a design error and must be resolved before implementation.

# 5. Exact Owner Mapping Rules

## 5.1 Owner Discipline
Codex must extend existing live owners first.

Before creating any file, ask:
1. Which existing owner already governs this domain?
2. Can this concept be implemented as added logic in that owner?
3. Can it instead be implemented as a derived projection?
4. Is it actually a law or lens rather than a runtime system?

If the answer to (1) or (2) is yes, **do not create a new owner**.

## 5.2 New File Creation Threshold
A new file may be created only when:
- no existing owner can absorb the responsibility without violating cohesion,
- the new file still lives under an existing owner subtree,
- it does not create a second authority path,
- it does not mirror existing truth.

## 5.3 Product Layer Discipline
Product-facing owners may:
- compress,
- frame,
- summarize,
- compare,
- preserve continuity projections,
- guide return / threshold experience,

but may **never**:
- own gameplay authority,
- become a hidden simulation layer,
- become a shadow runtime truth model.

# 8. Constitutional Laws (Must Be Enforced In Code and Review)

These are laws, not optional guidelines.

## 8.1 Structural Laws
- No second truth model.
- No second shell.
- No second archive.
- No detached civilization layer above expedition play.
- No parallel authority path for continuity, shell, archive, or governance.

## 8.2 Play Primacy Laws
- Expedition meaning remains primary.
- Player action must remain a primary driver of continuity change.
- The system may guide, bias, compress, or interpret continuity, but must not fully determine continuity change without player action.
- No system may replace player-driven outcomes with system-resolved outcomes.
- Every higher-order process must cash back into embodied expedition consequence.
- Route, burden, custody, witness, rescue, extraction, timing, and ecology remain final grounding surfaces.

## 8.3 Continuity Laws
- Nothing meaningful is deleted.
- Meaning may be compressed, layered, made dormant, or recontextualized.
- Meaningful continuity must remain recoverable, influence-bearing, or reactivatable.

## 8.4 Ordinary-Play Laws
- Ordinary sanctioned play remains fully real and sufficient.
- Deeper systems may enrich ordinary play but may never retroactively invalidate it.
- Quiet and non-performative play remain legitimate civilization relations.

## 8.5 Epistemic Laws
- Truth layers remain separated.
- Surface disclosure is budgeted.
- Some contradiction must persist.
- Some contradiction may converge.
- Governance remains humble before what exceeds classification.

## 8.6 Habitation Laws
- No humiliation engine.
- No coercive prestige ladder.
- No mandatory deep-reader monoculture.
- Unequal capacities for engagement must still receive meaningful civilization weight.

## 8.7 Renewal Laws
- Freshness must come from recombination, re-legibility, dormancy shifts, or phase change.
- Freshness must not depend on replacement or invalidation of the past.
- Mercy / release is a right.
- Wonder must survive stewardship.
- The future must remain hospitable to the not-yet-classified.

# 13. Anti-Parallel-Architecture Safeguards

Codex must reject any implementation that does any of the following:

- creates a second shell logic path,
- creates a second archive or memory authority,
- duplicates runtime truth in product code,
- mirrors continuity into a second governance model,
- introduces detached managers that restate existing owners,
- builds new “meta” systems when a law or lens would suffice,
- encodes philosophy as runtime bureaucracy instead of constraints.

## Explicit rejection pattern
Before accepting a new subsystem, answer:
1. Which active stack owns this?
2. Which existing owner path will carry it?
3. Is this actually a projection instead?
4. Is this actually a law or stewardship lens instead?
5. Does this create a second authority path?

If (3), (4), or (5) are true, reject or refactor.
