# Items and Synergies

See also: [MECHANICS](d:/DeductionDelve/docs/MECHANICS.md), [ARCHIVE_SYSTEM](d:/DeductionDelve/docs/ARCHIVE_SYSTEM.md), [LEVEL_GEN](d:/DeductionDelve/docs/LEVEL_GEN.md).

## Item Philosophy
Items in The Delve Protocol are social objects as much as tools. They shape movement, burden, route control, rescue, temptation, refusal, spectacle, and memory.

## Taxonomy
The live taxonomy stays unchanged:
- Artifacts
- Tools
- Relics
- World Objects

## Item Ecology
Items should be authored and interpreted through:
- traversal role
- burden role
- rescue role
- confrontation role
- witness visibility
- branch affinity
- temptation value
- cultural reputation

## Artifact Lineage
The live repo now emits compact product-only hints around:
- rescue association
- scandal association
- branch association
- prestige or fear

Future phases can still deepen:
- superstition
- shorthand readiness

## Social Handling
Meaningful handling patterns include:
- offering
- refusing
- handoff
- solo-carry
- burden transfer
- public drop
- loaded refusal

These are interpreted by the product layer, not by a second gameplay system.

## Current Live Implementation
The live repo already includes:
- deterministic item definitions
- additive narrative/item-ecology profiles
- deterministic spawn weighting that reads branch affinities, reduced protocol labels, and existing room-context memory seeds
- product-side lineage, branch-marker, memory, and prestige signaling through diagnostics, crawl memory, Archive comparison, and world memory
- a live pickup pool of:
  - Lantern Snuffer
  - Heavy Boots
  - Timeline Bookmark
  - Decoy Emitter
  - Zipline Kit
  - Custody Seal
  - Witness Chime
  - Echo Lure
  - Burden Sling
- bounded item-use consequence through the existing host owner path for custody stabilization, witness shaping, route redirection, and burden support

Future phases deepen that live base into stronger lineage, plurality, and social burden rather than replacing item ownership.
